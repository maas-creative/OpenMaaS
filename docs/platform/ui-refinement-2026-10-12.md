# 経路検索を中心とするUI点検と修正

## 結果

経路検索の主操作が弱く、補助ボタンが連続して読まれること、移動区間が文章だけで続くこと、発車予定を閉じられないことを修正した。共通ナビゲーションは1280px未満でメニューに切り替え、現在のページを文字の太さと下線でも示す。

- 検索ボタンを主操作として表示。出発地入替と現在地取得に間隔を設けた。
- 優先条件と乗換上限はネイティブの開閉要素へ収めた。選択値は閉じても保持する。
- 経路候補の時刻を強調し、選択中を文字でも表示する。
- 経路詳細を枠でまとめ、徒歩・乗車・到着の各区間を番号と線で追えるようにした。日付を保持して秒を省き、日をまたぐ経路も識別できる。
- 発車予定を再取得せず開閉できるようにした。区切り線で便を分ける。
- APIのfirstは0時以降の最初の便を意味するため、「この日の最初の便（0時以降）」と表示する。
- 保存ボタンは保存中・保存済みを表示。ログイン必須の判定は既存APIが行う。
- サービス申込みに共通スタイルと読み込み表示を適用。接続が空なら空の選択欄の代わりに状態と活動検索へのリンクを表示する。
- 未ログインの予定画面にログインへのリンクを設けた。

## 確認

UI Doctorの操作階層・情報量・フォーカスの観点とPonytail reviewを使用。IDSは採用していないため、IDSへの置換は行わず既存のCSS、標準HTML、Reactを利用した。

- 実際のTransit APIを通して東京駅→新宿駅、2026-10-12 09:00の経路6件を表示。
- 390pxで比較と区間表示、発車予定の取得と開閉、地図の表示を操作。
- 320pxの経路画面はbody幅305px、viewport320pxで横はみ出しなし。未ログイン保存はログイン要求を表示。
- 活動検索の空状態を320pxで視覚確認。
- 本番ビルドを起動し、サービス未接続の案内、予定画面のログイン導線、1024pxの共通メニュー開閉を確認。
- 1280pxで横並びナビゲーションと現在ページ表示を視覚確認。body幅1265px。
- 自動試験76件成功。API型検査・Next.js本番ビルド成功。lintはエラー0、既存警告89。ブラウザーのエラーログなし。

## Ponytail review

What this change does: Makes route search and route steps easier to read, and shows a useful next action on empty or signed-out screens.

入力・経路取得・予定保存のAPI契約は変更していない。既存の経路詳細呼出元（活動詳細、予定、再検索）を照合した。時刻は各経路のタイムゾーンを保持する。発車予定の状態は乗車地点と時刻のkeyで切り替わり、別経路の結果を混ぜない。追加ライブラリ、取引操作、秘密情報はない。

Verdict: Ship.
