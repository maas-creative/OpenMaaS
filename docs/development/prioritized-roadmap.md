# OpenMaaS 統合型MaaSプラットフォーム優先タスク

以下は、OpenMaaS が統合型 MaaS プラットフォームを目指すうえで優先して進めるべき主なタスク群を整理したロードマップです。各カテゴリで目的、キーユースケース、優先アクション、完了条件を明確にし、段階的な実施計画に落とし込みます。

## 1. マルチモーダル交通統合の基盤構築
- **目的**: 各交通モードのデータを統合し、都市交通の全体像をリアルタイムに把握できる状態を作る。
- **主要ユースケース**
  - 利用者向け経路検索と予約の統合体験
  - 運営側の交通リソースの可視化と配分最適化
- **優先アクション**
  1. マイクロサービス (Auth / User / Transit / Route / Booking / Payment) の API 契約とイベントスキーマを定義
  2. サービス間メッセージング (例: gRPC / Async API) とデータ正規化レイヤーの設計
  3. 各交通モードの外部データソース (GTFS, ライドシェア API, マイクロモビリティ) のコネクタ実装
  4. 都市交通データレイク (PostgreSQL + PostGIS もしくは Data Warehouse) への統合 ETL パイプライン構築
- **完了条件**
  - サービス間でユーザー・路線・予約情報を一元的に参照可能
  - CI 上で API コントラクトテストが自動実行される

## 2. セキュリティと決済フローの実装
- **目的**: 利用者と事業者双方が安心して決済・認証を行えるエンタープライズ水準の安全性を確保する。
- **主要ユースケース**
  - モバイルチケットの動的 QR コード発券
  - 事業者ロール別のダッシュボードアクセス制御
  - Stripe ベースの決済処理と不正防止
- **優先アクション**
  1. Keycloak 連携によるロールベースアクセス制御 (RBAC) と多要素認証の導入
  2. Stripe Checkout / Payment Intent を用いた決済フロー設計と Webhook ハンドリング
  3. QR チケットの生成・検証サービス構築 (短期有効な署名付きトークン)
  4. セキュリティ監査ログ、脆弱性スキャン、ペネトレーションテストのパイプライン整備
- **完了条件**
  - RBAC と決済が E2E テストで検証され、セキュリティポリシーに準拠
  - 不正利用検知のモニタリングがダッシュボードで可視化

## 3. ユーザー体験 (UX) の強化
- **目的**: どのデバイスからでも快適に利用できるモダンな体験を提供する。
- **主要ユースケース**
  - モバイルブラウザでの PWA インストールとオフライン利用
  - ライブ交通情報のリアルタイム同期
- **優先アクション**
  1. Next.js / React ベースのフロントエンドを PWA 対応 (Service Worker, Manifest)
  2. IndexedDB / Cache Storage を使ったオフラインキャッシュと差分同期戦略の実装
  3. WebSocket / SSE によるリアルタイム更新機構を UI と統合
  4. デザインシステム (レスポンシブレイアウト、アクセシビリティ) の整備
- **完了条件**
  - Lighthouse 監査で PWA スコア 90 以上を達成
  - 主要ユーザーストーリーがデバイス横断で QA 合格

## 4. 開発者向け API とドキュメント整備
- **目的**: 外部開発者やパートナーがサービスを拡張しやすいエコシステムを構築する。
- **主要ユースケース**
  - パートナー企業が REST / GraphQL API を利用して独自アプリを実装
  - サードパーティによるデータ可視化ツール連携
- **優先アクション**
  1. RESTful API のリソース設計とバージョニング戦略の確立
  2. OpenAPI / Swagger ドキュメントと API Explorer の公開
  3. 開発者ポータル (認証、API キー管理、サンプルコード) の整備
  4. SDK / Postman コレクション / Quick Start ガイドを提供
- **完了条件**
  - API コールの平均レスポンス SLA を定義し、モニタリング可能
  - ドキュメントが CI により自動生成・公開される

## 5. インフラと運用基盤の構築
- **目的**: スケーラブルで信頼性の高い運用環境を実現する。
- **主要ユースケース**
  - マイクロサービスを Kubernetes 上で自動スケーリング
  - 地理情報処理を PostGIS / Redis で高速化
- **優先アクション**
  1. Docker Compose から Kubernetes (Helm / Kustomize) へのデプロイ移行計画策定
  2. PostgreSQL + PostGIS、Redis、メッセージブローカー (Kafka / NATS) の IaC 化
  3. Kong Gateway と Keycloak の統合、サービスメッシュ (Istio / Linkerd) 検討
  4. Observability (Prometheus, Grafana, OpenTelemetry) の統合ダッシュボード構築
- **完了条件**
  - ステージング環境でのブルーグリーンデプロイが自動化
  - SLA / SLO に沿った運用監視が実施される

## 6. セットアップと検証手順の実行
- **目的**: 新規参加者が迅速に開発環境を構築し、主要機能を確認できるようにする。
- **主要ユースケース**
  - リポジトリ clone からサービス起動、デモユーザーログインまでの一連の Quick Start
- **優先アクション**
  1. `.env.example` の整備と Secrets 管理方針の明文化
  2. Makefile / npm scripts を利用した統一的なセットアップスクリプト
  3. docker-compose / Kubernetes のスタック起動確認と smoke test 実施
  4. デモユーザーのシードデータと自動検証スクリプト作成
- **完了条件**
  - Quick Start 手順が CI で定期検証される
  - 新規参加者アンケートで 90% 以上が「セットアップが容易」と回答

## 7. ロードマップ項目の推進
- **目的**: 現在進行中および将来計画の施策を可視化し、投資判断を容易にする。
- **主要イニシアチブ**
  - Mapbox / Google Maps の本番連携
  - 国際化 (i18n) 対応と言語追加
  - スマートフォン Web アプリ拡張
  - 機械学習による需要予測、データ分析基盤の整備
- **優先アクション**
  1. 各項目の技術検証 (PoC) と本番導入ロードマップを策定
  2. KPI / OKR を設定し、進捗トラッキングダッシュボードを用意
  3. 将来拡張 (AI/ML, 分析基盤) のためのデータガバナンス整備
- **完了条件**
  - 四半期ごとのロードマップレビューで進捗と課題を共有
  - 新規施策の PoC 成果が意思決定に活用される
