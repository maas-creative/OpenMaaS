ソフトウェアを共有し、地域のサービスづくりに力を注ぐ

MaaS（Mobility as a Service）は、複数の移動手段を利用者の目的に合わせて組み合わせ、検索・予約・利用までをつなぐ考え方です。OpenMaaSは、その目的となるイベント・体験・施設・宿泊も交通と結び付けます。

地域ごとに同じ検索画面や接続処理を作り直す負担を減らせば、交通事業者や活動の提供者との連携、利用者の困りごとの理解、サービスを続ける仕組みに力を注げます。OpenMaaSは、そのための共通のソフトウェアを提供します。

対象地域、情報源、利用サービス、接続資格情報を導入先が設定します。運営や販売の主体、事業者との契約は導入先が担います。

目的の検索から、移動・申込み・予定の確認まで

  1. 目的を選ぶ

    日時・場所・カテゴリからイベント、体験、施設、宿泊を探す。

  2. 移動を調べる

    開始時刻に間に合う往路と、終了後の帰路を検索する。

  3. 申し込む

    サービスが提供する申込み先や、対応するAPI予約を利用する。

  4. 予定を確認する

    活動、交通、宿泊、券をまとめ、変更や中止を確認する。

保存した予定と確定予約は区別します。複数サービスを追加しても、一括予約・一括取消が成立したとは扱いません。オンラインイベントには移動案内を付けず、終了時刻や会場座標が不明な場合は必要な情報の入力を求めます。

四つの導入例

イベントからの交通案内

Luma・connpassのイベントから、会場への到着検索と帰路検索へ。参加申込みは提供元へ案内します。

観光周遊

体験、宿泊、公共交通、シェア交通を予定へ。地域で利用できるサービスを組み合わせます。

生活交通案内

停留所・時刻表・運行情報やシェア交通の空き状況を、日々の移動の判断につなげます。

導入先商品の券販売

Stripe Checkoutを使い、購入・発券・オンライン認証・返金を扱います。参照用一回券を同梱しています。

四つの設定例を同梱しています。利用する接続・対象地域・取得条件・表示順・対応操作を設定で切り替えられます。

交通と、移動の目的になるサービスを接続。

情報取得、外部サイトへの案内、API予約はサービスごとに異なります。対応する操作だけを利用できる構成です。

分野接続・標準実装している範囲
公共・シェア交通GTFS / GTFS-RT / ODPT / GBFS時刻表、停留所、運行情報、ポート・車両の空き状況とデータの鮮度。
経路検索OpenTripPlanner / 駅すぱあと出発・到着日時を指定した検索。導入先が経路検索サービスを選択。
イベントLuma / connpass / Eventbrite / Ticketmaster権限・契約の範囲内で取得し、参加・購入先へ案内。Luma参加者名簿は取り込みません。
宿泊楽天トラベル / Booking.com Demand / Expedia Rapid楽天は施設・空室検索と外部予約案内。Booking.com・Expediaは対応する契約・支払方式のAPI予約・照会・取消。
体験・施設・配車Viator / Square Bookings / Uber Guest Rides提供元の仕様に沿った検索、予約、状態照会、取消。利用資格・対象地域の確認が必要。
駐車場TomTom Parking Availability空き状況の取得。駐車場の予約機能ではありません。
予定・導入先商品の決済iCalendar / Google Calendar / Stripe CheckoutICS出力、利用者認可による予定登録・更新、導入先商品の決済・照会・返金。

提供元が決済するサービスは、その購入フローを利用します。OpenMaaSのStripe決済で重ねて請求しません。APIの存在だけで利用資格や販売契約が得られるわけではありません。

設定と資格情報から、導入を始める。

  1. 構成を選ぶ

    四つの設定例から選び、地域・Web/APIのURL・OIDC認証を設定します。

  2. 利用する接続を設定する

    データのURL、対象カレンダー、取得期間などを設定し、APIキーはSecretsに登録します。管理画面で接続を診断します。

  3. 配置して、利用を確かめる

    Next.js / OpenNextとHono APIをCloudflare Workers・D1・R2に配置し、実際の利用範囲で確認します。配置CLIと導入手順を同梱しています。

現在の検証範囲

自動試験56件、API型検査、Web本番ビルド、Worker bundle、公開交通フィードの取得・ローカル取込とブラウザー操作を確認しています。商用接続は仕様に基づく試験用応答で検証しています。

商用アカウントでの実取引とOpenMaaSアプリの本番配置は未検証です。Masabiの固有発券接続と追加3DS認証フローは未実装です。導入時には接続資格・利用条件と実環境での成立・取消・復旧を確認します。

コードの公開とAGPLライセンス

コードを公開し、AGPL-3.0-or-laterで提供します。商用利用も可能です。改変版をネットワーク経由で提供する場合は、利用者に対応するソースコードを入手する手段を提示します。地域で生まれた改善を共有できることを、ソフトウェアの基盤にしています。

APIキーや利用者情報を公開する必要はありません。取得データ・外部API・依存ライブラリには、それぞれの利用条件が適用されます。
